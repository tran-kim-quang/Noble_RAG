Storage Backend Implementation Guide
=====================================

Architecture:
- PostgreSQL: Chunks, entities, relations, doc status
- Qdrant: Vector embeddings
- Redis: Session/conversation cache
- MongoDB: Optional alternative for graph


INITIALIZATION STEPS
====================

1. PostgreSQL Setup
-------------------

Create tables for entities and relations:

CREATE TABLE entities (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    entity_name VARCHAR(255) UNIQUE NOT NULL,
    entity_type VARCHAR(100),
    description TEXT,
    embedding VECTOR(3072),
    metadata JSONB,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP
);

CREATE TABLE relations (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    source_entity_id UUID NOT NULL REFERENCES entities(id) ON DELETE CASCADE,
    target_entity_id UUID NOT NULL REFERENCES entities(id) ON DELETE CASCADE,
    relation_name VARCHAR(255),
    weight FLOAT,
    description TEXT,
    embedding VECTOR(3072),
    metadata JSONB,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

CREATE INDEX idx_entity_name ON entities(entity_name);
CREATE INDEX idx_entity_type ON entities(entity_type);
CREATE INDEX idx_relation_src ON relations(source_entity_id);
CREATE INDEX idx_relation_tgt ON relations(target_entity_id);
CREATE INDEX idx_relation_name ON relations(relation_name);

Enable pgvector extension for vector operations:
CREATE EXTENSION IF NOT EXISTS vector;


2. Qdrant Setup
---------------

Collections are auto-created by LightRAG when needed.
No manual setup required.

To verify Qdrant is running:
curl http://localhost:6333/health

Response should be:
{
    "title": "Qdrant",
    "version": "..."
}


3. Redis Setup
--------------

Redis is auto-configured via docker-compose.

To test Redis connection:
redis-cli ping
# Response: PONG

To check Redis memory:
redis-cli info memory


4. MongoDB Setup (Optional)
---------------------------

Only enable if USE_MONGODB_FOR_GRAPH=true in .env

Create collections:
use noble_rag

db.createCollection("entities")
db.createCollection("relations")

Create indexes:
db.entities.createIndex({ entity_name: 1 }, { unique: true })
db.relations.createIndex({ source_entity_id: 1 })
db.relations.createIndex({ target_entity_id: 1 })

WORKING WITH STORAGE
====================

Data Flow:

1. Insert Document
   Document --> Split into Chunks --> Store in PostgreSQL (kv_store)

2. Extract Graph
   Chunks --> LLM extraction --> Entities + Relations --> 
   PostgreSQL (entities, relations tables)

3. Create Embeddings
   Entities + Relations + Chunks --> Embedding Model --> 
   Qdrant (vector collection)

4. Query Processing
   User Query --> Vector search in Qdrant (semantic) --> 
   Join with PostgreSQL (hierarchical) --> 
   Cache in Redis (session) --> 
   Return answer


MONITORING STORAGE
==================

PostgreSQL:
  Check table sizes:
  SELECT schemaname, tablename, pg_size_pretty(pg_total_relation_size(schemaname||'.'||tablename)) 
  FROM pg_tables 
  WHERE schemaname NOT IN ('pg_catalog', 'information_schema');

  Check entity count:
  SELECT COUNT(*) FROM entities;
  SELECT COUNT(*) FROM relations;

  Check slow queries:
  EXPLAIN ANALYZE SELECT * FROM entities WHERE entity_name = 'Google';

Redis:
  Monitor key count:
  redis-cli DBSIZE

  Check session expiry:
  redis-cli TTL session_key

  Memory usage:
  redis-cli INFO memory | grep used_memory_human

Qdrant:
  List collections:
  curl http://localhost:6333/collections

  Get collection stats:
  curl http://localhost:6333/collections/collection_name


BACKUP & RECOVERY
=================

PostgreSQL Backup:
  pg_dump -U rag_user -d noble_rag > backup.sql
  
Restore:
  psql -U rag_user -d noble_rag < backup.sql

Qdrant Backup:
  Stored in qdrant_data volume
  Docker backup:
  docker cp noble_rag_qdrant:/qdrant/storage ./qdrant_backup

Redis Backup:
  redis-cli SAVE
  Or rely on AOF persistence (appendonly yes)


TROUBLESHOOTING
===============

PostgreSQL Connection Issues:
  Error: could not connect to server
  Solution:
    1. Check postgres service running: docker-compose ps
    2. Verify credentials in .env
    3. Check network: docker network ls

Qdrant Connection Issues:
  Error: connection refused
  Solution:
    1. Check Qdrant service: docker-compose ps
    2. Verify URL in .env matches service config
    3. Check health: curl http://localhost:6333/health

Redis Connection Issues:
  Error: connection refused
  Solution:
    1. Check Redis service: docker-compose ps
    2. Verify port matches .env
    3. Test: redis-cli ping

Vector Search Slow:
  Solution:
    1. Check Qdrant collection size
    2. Verify indexes exist
    3. Monitor memory usage
    4. Consider increasing QDRANT allocation

Duplicate Entities:
  Cause: Race condition during extraction
  Solution:
    1. Use unique constraint on entity_name
    2. Implement entity deduplication logic
    3. Check LLM cache settings (ENABLE_LLM_CACHE)


PERFORMANCE TUNING
==================

PostgreSQL:
  - Increase shared_buffers (25% of RAM)
  - Enable parallel queries: max_parallel_workers = 4
  - Tune work_mem based on available RAM
  - Monitor vacuum frequency

Qdrant:
  - Batch insert operations for speed
  - Use appropriate metric (cosine by default)
  - Enable quantization for large collections
  - Monitor memory vs performance trade-off

Redis:
  - Monitor eviction policy (allkeys-lru by default)
  - Tune maxmemory setting
  - Consider blocking operations timeout


MIGRATION BETWEEN BACKENDS
===========================

From Local to PostgreSQL:
  1. Keep local storage running
  2. Init PostgreSQL schema
  3. Run migration script to copy data
  4. Point LightRAG to PostgreSQL (update .env)
  5. Verify data integrity
  6. Archive local storage

From PostgreSQL to MongoDB Graph:
  1. Set USE_MONGODB_FOR_GRAPH=true in .env
  2. Init MongoDB collections
  3. Run migration script
  4. Verify entity/relation counts match
  5. Test graph queries

Example migration approach:
  for entity in entities_from_source:
      insert into target_backend(entity)
      verify count matches

RECOMMENDATION SUMMARY
======================

Use PostgreSQL + Qdrant + Redis for:
  Production deployments
  Knowledge graph storage
  Session management
  Vector similarity search
  Balanced cost and performance

  - Scalable from 1K to 10M+ entities
  - ACID compliant for data integrity
  - Cost effective for self-hosted
  - Easy to monitor and backup
